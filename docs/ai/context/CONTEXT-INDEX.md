# Context index

Start here. This page says where each kind of fact lives and which part to read for a task. It links to the records and does not copy them. The repo docs stay the authority.

## Where facts live

| Fact | Authority | What to read |
|---|---|---|
| Project state, next action, open decisions | [docs/PROGRESS.md](../../PROGRESS.md) | "Resume here" only |
| What the lead is doing now | [CURRENT-WORK.md](CURRENT-WORK.md) | all of it (short) |
| Requirements | [docs/spec/ORIGINAL_SPEC.md](../../spec/ORIGINAL_SPEC.md) | the requirement you work on |
| Affordability formulas | [docs/spec/affordability-rules.md](../../spec/affordability-rules.md) | the rule you touch |
| A phase's plan, decisions, tests, gates and open issues | `docs/progress/phase-NN-*.md`, `docs/progress/harness-NN-*.md` | the section your task names |
| Every decision, one line each | [DECISIONS.md](DECISIONS.md) (generated) | find the ID, then open the linked source |
| Open issues and carry-overs | [OPEN-ITEMS.md](OPEN-ITEMS.md) (generated) | the rows for your phase |
| Architecture decisions | [docs/adr/](../../adr/) | the ADR a row links to |
| Agents: role, boundaries, model and why | [AGENT-REGISTRY.md](AGENT-REGISTRY.md) | your own section |
| Work handed between agents | [handovers/](handovers/) and [HANDOVER-TEMPLATE.md](HANDOVER-TEMPLATE.md) | the newest handover for your task |
| Coding, git and commit rules | [AGENTS.md](../../../AGENTS.md), [CLAUDE.md](../../../CLAUDE.md) | loaded automatically |
| Security rules | [.claude/rules/security.md](../../../.claude/rules/security.md) | loaded automatically |
| How agents, hooks and gates fit together | [docs/ai/ORCHESTRATION.md](../ORCHESTRATION.md) | when you change the harness |
| Prompt history and design reasoning | [docs/ai/PROMPTS.md](../PROMPTS.md), [docs/ai/DESIGN-JOURNAL.md](../DESIGN-JOURNAL.md) | only when a task asks for history |
| Usage snapshot, checkpoint, blocker (local, not committed) | `.claude/state/usage.json`, `checkpoint.md`, `blocker.md` | shown by the brief and at session start |

## What to read for which task

| Task | Read | Do not read by default |
|---|---|---|
| Implement an approved plan | phase file "Plan", "Decisions" and the approved tests; CURRENT-WORK | PROMPTS.md, the journal, other phases |
| Review a diff (`dotnet-reviewer`) | the diff, the touched files, AGENTS.md; the rules doc if the maths changed | the implementer's report, earlier review findings |
| Security gate (`security-auditor`) | the diff, `.claude/rules/security.md`, scanner output | earlier review findings |
| Spec check (`spec-checker`) | ORIGINAL_SPEC.md, the traceability table in PROGRESS.md, code and tests | phase prompts |
| Design tests (`test-designer`) | phase "Plan", the spec, the code under test | earlier test results |
| Resume after a break or a usage limit | PROGRESS "Resume here", CURRENT-WORK, `.claude/state/checkpoint.md` and `blocker.md` if present | whole phase files |
| Find a past decision | DECISIONS.md, then the linked row or ADR | whole phase files |

## Generated files

`DECISIONS.md` and `OPEN-ITEMS.md` are generated by `scripts/context/index.sh` from the phase files, the ADRs and PROGRESS.md. Do not edit them. After changing a "Decisions" table, an "Open issues" list, an ADR header or a carry-over, run `scripts/context/index.sh` and commit the result. `./scripts/verify.sh` (full) runs `scripts/context/index.sh --check`, which fails when either file is stale or a source or handover is malformed.

## Briefs

`scripts/context/brief.sh <agent> [phase]` prints the short brief an agent starts from. The `SubagentStart` hook adds it to every subagent; the lead also names it in the prompt.
