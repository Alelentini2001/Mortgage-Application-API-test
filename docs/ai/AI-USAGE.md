## 2. Which Agents Were Responsible for Implementation, Testing & Reviews

All subagents are defined in [`.claude/agents/`](../../.claude/agents/) and documented in [`docs/ai/context/AGENT-REGISTRY.md`](context/AGENT-REGISTRY.md). Subagents never see the lead agent's conversation history; each starts with a clean context window and receives only the files and scope in its logged prompt.

| Agent | Role | Tool Boundaries | Model (`Claude Code` → `Antigravity`) | Responsibility |
|---|---|---|---|---|
| **Lead agent / `parallel-implementer`** | Implementation & coordination | Full read/write/test (`parallel-implementer` isolated in a git worktree for Phases `04` and `06`; sequential phases implemented by the lead after `P06-12`) | `Claude Opus 5.5` → `Gemini 4 Argon` | Drafts phase plans and trade-offs for Checkpoint A, writes failing tests first from approved `test-designer` proposals, implements production code in small conventional commits, runs `./scripts/verify.sh`, and records evidence |
| **`test-designer`** | Test design (pre-code) | **Read-only** (`Read`, `Grep`, `Glob` only; no `Edit`, `Write`, or `Bash`) | `Claude Sonnet 4.6` → `Gemini 4 Argon` | Proposes unit, integration, boundary, negative, and security test cases (`docs/progress/phase-NN/test-proposal.md`) *before* any test or feature code is written; surfaces spec ambiguities for Alessandro |
| **`security-auditor`** | Security gate | **Read-only** by instruction + scanner execution (`gitleaks`, `semgrep`, `dotnet list package --vulnerable`) | `Claude Opus 5.5` → `Gemini 4 Argon` | Runs Gitleaks (full git history + working tree), Semgrep (`p/csharp` + `p/secrets`), and NuGet vulnerability audits; reviews `git diff main...HEAD` against OWASP Top 10:2025 and `.claude/rules/security.md` |

| **`spec-checker`** | Requirement traceability | **Read-only** (`Read`, `Grep`, `Glob` only) | `Claude Sonnet 4.6` → `Gemini 4 Argon` | Maps all 55 atomic requirements (`R1`–`R55` in `docs/spec/ORIGINAL_SPEC.md`) and phase decisions to exact `file:line` and test names in `docs/PROGRESS.md` |

## 4. How AI Work Was Independently Verified

1. **Independent Python `decimal` recomputation before any C# code (Phase 1):**
   - Worked examples `E1`–`E14` were independently recomputed in Python `decimal` at both `28`-digit and `50`-digit precision by a fresh-context `dotnet-reviewer` (`P01-02`) before `AffordabilityCalculator.cs` existed, and `E1`–`E19` are pinned as literal constants in [`GoldenCases.cs`](../../tests/MortgageApplications.UnitTests/Affordability/GoldenCases.cs) (never recomputed by the test).
2. **Strict Red-Then-Green TDD & Mutation Checks:**
   - Tests were written and committed failing first (e.g. `dbc93ad` and `0f4fcb1` in Phase 9, `317d493` in Phase 8, `83b2bd3` in Phase 7). Where a reviewer questioned whether a test could fail (Phase 2 rounding/comparison rules, Phase 5 root-span and allowlist tests, Phase 6 worker queue tests, Phase 9 WAL migration test), the production code was deliberately broken or tested against a pre-fix state to prove the test failed red.
3. **Fresh-Context & Cross-Model Gate Separation:**
   - Every phase ran `security-auditor`, `dotnet-reviewer`, and `spec-checker` in isolated subagent contexts that received only `git diff main...HEAD` and the spec/rules files.
   - Switching from **Claude Opus 5.5** to **Gemini 4 Argon** mid-way through Phase 7 (`3320a82`) proved the value of cross-model review: Gemini 4 Argon's `dotnet-reviewer` immediately spotted the unredacted record `ToString()` on `DevTokenRequest`/`DevTokenResponse` and the duplicate `"sub"` JSON key vulnerability in `SubjectClaim.IsJsonString`.
4. **Deterministic Local & CI Verification Gates:**
   - [`./scripts/verify.sh`](../../scripts/verify.sh) enforces locked NuGet restore (`--locked-mode`), Release build with `TreatWarningsAsErrors`, all **586 automated tests** (`275` unit + `311` integration), **113 bash hook regression cases** ([`.claude/hooks/tests/test-hooks.sh`](../../.claude/hooks/tests/test-hooks.sh)), and `dotnet format --verify-no-changes`.
   - [`.githooks/pre-commit`](../../.githooks/pre-commit) runs `gitleaks` on every commit, and [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) runs both the full `.NET` verification suite and a live Docker Compose build + end-to-end smoke test (`GET /health`, non-root UID check, `401` anonymous check, `POST /dev/token`, `POST`/`GET /api/applications`, and `202` → `Completed`/`Approved` assessment polling).
